Collect the information required to draft and apply a high-quality commit message.

Scope:
- Focus only on understanding the current uncommitted changes.
- Analyze and commit only staged changes when staged changes exist.
- If there are no staged changes, analyze and commit all current uncommitted changes.
- Do not propose new code changes.
- Do not execute destructive commands.
- Run `git commit` directly using the generated message.

Gather:
- What changed: key files and the most relevant modifications.
- Why it changed: inferred intent or problem being solved.
- Impact: behavior, UX, DX, performance, or operational effects.
- Validation: explicitly run lint and unit tests, and report results (or clearly report missing validation and why).
- Risks: edge cases, regressions, or follow-up considerations.

Output format:
1) `title_candidate`: one imperative commit title, without conventional prefixes (`feat:`, `fix:`, etc.) and without issue numbers.
2) `commit_context`: a concise but complete summary to use as the commit body.
3) `missing_context`: explicit unknowns that should be confirmed before finalizing the commit message.
4) `final_commit_message`: final text to use in the commit (title + blank line + body).

Apply step:
- Before commit, ensure lint and unit tests pass for the selected scope.
- Run `git commit` using `final_commit_message` without asking for confirmation.

Style constraints:
- Keep everything concrete and repository-specific.
- If referring to identifiers, use «identifier».
- Replace backticks with «...».
